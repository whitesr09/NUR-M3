# NUR-M3 — levels 0.21–0.25

Source-only development continues from commit `0c8597173ba07ecb96e40cd3f11a8f2f0a18e82d` on `development/levels-015-020`. No APK build, pull request, main-branch merge, or production release is requested for this pass. The 0.15–0.20 document remains a design boundary and is not proof that every earlier module is production-complete.

## 0.21 Focus & Routine Studio

Implemented in source:
- Local Focus database for real session history and reusable routines.
- Foreground timer with pause, resume, cancel, completion, and interruption recovery.
- Monotonic elapsed-time accounting and millisecond checkpoints so background/process gaps are not invented as focused work.
- A session is counted completed only after its planned duration is actually reached and the completed record is persisted.
- Routine presets are separate from completion records.

Still required before release: compile/test pass, lifecycle testing on physical devices, rotation/process-death review, and long-session/battery behavior review.

## 0.22 NUR AI

Implemented in source:
- Optional Gemini chat with an explicit NUR AI network-access toggle and a user-owned API key.
- API key, selected model, and local AI history are stored in NUR's Keystore-backed private store and excluded from backups/widgets.
- Stable default model `gemini-2.5-flash`, editable model ID, and quick model presets.
- Server-Sent Events streaming through Gemini `streamGenerateContent`; partial readable text is shown while generation continues.
- Optional Google Search grounding. Source links are displayed only when grounding metadata is actually returned.
- Local history removal, API-key removal, model reset, and a clear-all AI action.
- System instruction explicitly prevents fabricated Quran/Hadith quotations or claimed religious rulings and asks the model to state uncertainty.

No network request is sent merely by opening NUR AI or saving settings. A request is sent only after AI networking is enabled and the user submits a message. AI output remains unverified explanatory content, not a religious authority.

Still required before release: live API-key/quota testing, model-availability testing, streamed error/cancellation tests, and religious-content review of the user-facing safety copy.

## 0.23 Widgets & Quick Actions

Implemented in source:
- Separate Daily Light, prayer, Amanah, and quick-action Android widgets.
- Widgets read the existing Room records and date-scoped completion data; they do not maintain a second progress database.
- Distinct immutable pending intents for opening task creation, Dhikr, Focus, and app routes.
- Refresh requests on widget lifecycle, app data/date refreshes, boot/date/time/timezone changes, and manual refresh.
- Launcher pin/setup screen where supported.
- Widget output avoids private journal and AI conversation content.

Still required before release: launcher testing across Android/OEM variants, widget resizing review, background restriction testing, and visual review at supported cell sizes.

## 0.24 Privacy & Backup Pro

Implemented in source:
- Versioned portable encrypted backup using PBKDF2-HMAC-SHA256 and AES-256-GCM authenticated encryption with independent random salt and nonce.
- Bounded encrypted/plaintext sizes and bounded KDF parameters.
- Passphrase-controlled export; passphrases are not stored in the exported file.
- Authenticate/decrypt and preview before merge or replacement.
- Core records plus Focus sessions/routines in the encrypted portable snapshot; API credentials, AI history, app PIN material, and private journal content remain excluded.
- Existing legacy JSON backup compatibility is preserved.
- Replacement preserves encrypted local recovery snapshots through the Android Keystore-backed recovery vault.
- Read-only Backup Health screen runs SQLite quick checks, reports real saved counts, and reports whether recovery snapshots exist without modifying records.
- Unit-test source covers encrypted round-trip, wrong-passphrase rejection, tampering rejection, and unsupported/oversized envelope handling.

Still required before release: execute the full test suite, device-to-device encrypted restore testing, forced-failure recovery drills, and upgrade testing from existing installed NUR-M3 builds.

## 0.25 Accessibility & Final Experience

Implemented in source:
- Additional text scaling, high-contrast mode, reduced motion, and optional guidance preferences.
- App motion reduction is combined with the Android animator state; large accessibility text disables compact-card density.
- High-contrast mode now follows the actual system light/dark state when theme mode is `system`.
- Reviewed resource sets exist for selected English, Malayalam, and Arabic new-feature labels; Android locale metadata declares `en`, `ml`, and `ar`.
- RTL layout support remains enabled.
- First-launch feature guide plus a settings-accessible guided setup.
- New controls use Material semantics/touch targets where implemented, and capability notes avoid claiming unreviewed full translation or production readiness.

Still required before release: TalkBack traversal testing, large-font/small-screen clipping review, physical-device contrast review, complete translation review, and performance profiling.

## Current boundary

Levels 0.21–0.25 now have substantial source implementations on the development branch, but **they are not being declared production-complete**. Source has been written and some unit-test files have been added; the current pass intentionally did not trigger GitHub Actions or build an APK. Compilation, automated test execution, device QA, migrations/upgrade paths, and final release review remain gates before merge or release.

Existing NUR V2 repositories, the NUR-M3 `main` branch, package name, and signing identity remain unchanged by this source-only pass.
