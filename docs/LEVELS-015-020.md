# NUR-M3 levels 0.15–0.20

This source-only branch continues the completed 0.14 dashboard and font import. It must not be merged into main or used for a production release before compilation, unit tests, migrations, and physical-device review. No build is requested for these levels.

## 0.15 Appearance
Optional glass-like surfaces with restrained highlight, translucency, and configurable intensity/corners. Android 12+ window blur is available only for suitable windows. Ordinary Compose cards do not falsely claim to sample the backdrop. Independent ring/bar styles and stroke scaling, reduced-motion controls, and previews must remain separate from stored completion data. True-black AMOLED is preserved.

## 0.16 Amanah
Subtasks, priority, category, notes, due date/time, and reusable templates. Existing entries retain their IDs and dated history. Subtasks are personal task details, not extra Daily Light denominators. Archive keeps records; edits never replace immutable identity fields.

## 0.17 Reminders
User-controlled local reminders with Android notification permission, explicit schedules, cancellation, quiet hours, snooze and reboot restoration. No network service or exact-alarm privilege is assumed. Prayer reminders require verified calculated times and must not be invented from checklist order.

## 0.18 Prayer companion
Offline calculation with explicit location, timezone, method, madhhab and corrections. Show calculation provenance and distinguish estimated times from religious rulings. Never infer a user's precise location or claim a method is universally authoritative.

## 0.19 Quran reading
Preserve the existing curated reflection collection. Full-text reading requires a verified, licensed corpus and translation; no fabricated verses, audio or attribution. Bookmarks, favorites, reading position, and local collections can be implemented without changing the existing religious text.

## 0.20 Muhasaba journal
Private dated writing, prompts, tags, search, and optional authentication gate. The journal is not a mood diagnosis. Its records survive midnight and are never uploaded. Existing plaintext backup formats must not silently start exporting private journal content. Encrypted export requires a separately authenticated, versioned format.

## Data safety
Keep `com.nshd.nurm3` and the stable debug signing identity. Use additive Room migrations with no destructive fallback. Preserve existing v1–v3 backups, the actual completion timestamps, and old NUR repositories. Source-only work must not trigger GitHub Actions or create a pull request until a build is requested.
