# NUR 0.4 — Recovery and experience

This development branch starts from the last successful 0.3.0 commit. The original NUR applications and the 0.3.0 build remain untouched.

## Delivery order

1. Finish a validated, transactional backup/import workflow before any destructive or signing transition.
2. Add real privacy controls, live widget data, date-aware insights, and reduced-motion-aware transitions.
3. Integrate verified Islamic content and optional Gemini access only with explicit consent and private credentials.
4. Test upgrades from the 0.3.0 database and signing identity. Never delete or reset user data to repair a migration.

The early 0.1.0 APK may have a different signing certificate. A backup importer cannot automatically extract data from another installed app. Preserve that installation until a compatible export or a verified migration route is available. The public test key is not a production signing identity, and a private release key must never be committed.

A green CI run confirms that its configured tests and compilation passed. It is not a substitute for installing and testing an upgrade on an Android device. Features are marked complete only after their functional implementation and validation.
