Widgets use the existing Room entries and completion records; they must not invent checkmarks or maintain separate task counts. Quick actions open explicit in-app destinations and never mutate records from an exported receiver. Widget progress is date-scoped, with no fake history. Updates are requested on database changes, date/time changes, widget lifecycle events and periodic host refresh. The launcher controls exact scheduling; no claim is made that all hosts update at an exact second. Widgets show aggregate counts by default, not private journal or AI content. Disabling widgets hides their useful data. The source must be compiled and tested on a device before release.
